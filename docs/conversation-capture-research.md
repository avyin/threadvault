# Conversation Capture Research

Date: 2026-05-15

## Question

Can a Custom GPT/GPT Action store the whole conversation, meaning exact assistant and user messages from a ChatGPT conversation with a GPT, or is another approach required?

## Short Answer

Not reliably through GPT Actions alone.

GPT Actions can send data to an external API, and OpenAI says ChatGPT may send parts of a conversation to an action endpoint. But the official docs do not describe a GPT Action capability that lets an action fetch the full authoritative ChatGPT transcript or conversation object directly. The Action payload is generated by the model according to the OpenAPI schema, so it is best treated as a model-supplied transcript attempt, not a guaranteed exact export.

There is also a documented GPT Actions limit: request and response payloads must be less than 100,000 characters. That means long conversations cannot be captured whole in a single Action call.

## Evidence From Official Docs

OpenAI GPT Actions production notes:

- GPT Actions are external API calls from ChatGPT.
- Action calls have a 45 second round-trip timeout.
- Request and response payloads must be under 100,000 characters.
- For Action data usage, OpenAI says ChatGPT may send parts of the user's conversation to the action endpoint.

Source: https://developers.openai.com/api/docs/actions/production

OpenAI GPT Actions introduction/getting started:

- Actions use an OpenAPI schema to describe API calls.
- ChatGPT decides when an API call is relevant and generates JSON input for the call.
- Debugging in ChatGPT can be difficult; testing the API separately is recommended.

Sources:

- https://developers.openai.com/api/docs/actions/introduction
- https://developers.openai.com/api/docs/actions/getting-started/getting-started

OpenAI ChatGPT shared links FAQ:

- Shared links can include a snapshot of the entire conversation up to the point the link is created.
- Shared links are public to anyone with the link and do not provide granular permissions.

Source: https://help.openai.com/en/articles/7925741-chatgpt-shared-links-faq

OpenAI ChatGPT data export docs:

- Users can export ChatGPT data from account data controls.
- The exported zip includes chat history.
- Consumer Free/Plus/Pro exports are supported; ChatGPT Business/Enterprise exports are not available from that flow.

Source: https://help.openai.com/en/articles/7260999-how-do-i-export-my-chatgpt-history-and-data

OpenAI conversation transfer docs:

- A ChatGPT data export can include a `conversations.json` file.
- Uploading it into another account is only a workaround and does not recreate prior conversations one-to-one.

Source: https://help.openai.com/en/articles/9106926-transferring-conversations-from-1-chatgpt-account-to-another-chatgpt-account

## What GPT Actions Can Do

A Custom GPT can be instructed to call an endpoint such as:

```text
POST /api/conversations/save
```

and include fields like:

- `title`
- `summary`
- `messages`
- `raw_transcript`
- `client_reported_message_count`
- `notes_about_completeness`

This is useful for an experiment because it can show:

- whether the GPT will attempt to send a transcript at all;
- how many messages it includes;
- whether assistant/user wording appears exact;
- where the Action payload size limit is hit;
- whether the model omits older turns, system messages, tool traces, or attachments.

But it is not an authoritative export. The action receives only what ChatGPT/model chooses to put in the API call.

## What GPT Actions Cannot Be Assumed To Do

Based on the official docs reviewed, do not assume a GPT Action can:

- access a hidden canonical transcript object;
- request all previous messages from ChatGPT by conversation id;
- bypass payload limits by asking ChatGPT to attach its internal conversation state;
- guarantee exact assistant text, exact user text, system messages, tool calls, file contents, images, or timestamps;
- export arbitrary historical conversations after the fact.

## Alternatives

### 1. Keep Using ThreadVault As An Empirical Test Harness

This is the fastest path for the current experiment.

Use the Custom GPT instructions to ask the GPT to save the transcript when the user says goodbye. ThreadVault records:

- request size;
- message count;
- total characters;
- payload JSON;
- validation failures;
- ingest events.

Conclusion quality: good for discovering what ChatGPT actually sends through Actions in practice, but not a guarantee of exactness.

### 2. User-Initiated ChatGPT Data Export

For an authoritative account-level record, the user can use ChatGPT data export. This is asynchronous and manual, not an Action-triggered save.

Pros:

- Official export path.
- Intended to include chat history.
- Can include `conversations.json` according to OpenAI help docs.

Cons:

- Not available to logged-out users.
- Not available through the documented consumer flow for Business/Enterprise.
- Not real-time.
- Not scoped to one Action call.
- Requires the user to download and process the export.

### 3. Shared Links

A user can create a shared link for a conversation. The general shared-link docs say it is a snapshot of the entire conversation up to the share point.

Pros:

- Simple user-facing workflow.
- Captures what ChatGPT renders for that shared snapshot.

Cons:

- Public to anyone with the link.
- No granular permissions.
- Not an API export.
- May not include all modalities or files.
- Enterprise shared-link behavior differs from consumer shared links.

### 4. Build The Chat Experience Outside ChatGPT

If exact persistence is required, build the conversation UI yourself using OpenAI APIs such as the Responses API or a custom ChatKit integration.

Pros:

- Your app owns the transcript.
- Exact user/assistant messages can be saved at creation time.
- You can persist tool calls, metadata, timestamps, and attachments according to your own schema.

Cons:

- It is no longer a native ChatGPT GPT conversation.
- Requires building and operating a frontend/backend.

### 5. Browser Automation Or Scraping

This may be technically possible in a local browser, but it is brittle and likely a poor foundation.

Cons:

- Fragile against UI changes.
- Can run into terms, privacy, and security issues.
- Hard to make reliable across accounts, workspaces, and message types.

## Recommendation

For ThreadVault, continue treating GPT Action transcript saving as an empirical capability test, not a guaranteed export mechanism.

Recommended next experiment:

1. Start ThreadVault through ngrok.
2. Import `https://YOUR-NGROK-HOST/openapi.yaml` into the GPT Action editor.
3. Configure API key auth with `X-ThreadVault-Key`.
4. In the GPT instructions, ask it to call `saveConversationTranscript` when the user says goodbye and to include all visible user and assistant messages it can access.
5. Run conversations at increasing sizes.
6. Compare saved payloads against the visible ChatGPT conversation manually.
7. Record where omissions start and whether the payload approaches the 100,000-character request limit.

If the requirement is exact, reliable, complete storage, use a custom app/API flow where your server stores every turn as it happens.

## Practical Conclusion

Possible to store: a model-supplied near-transcript from a Custom GPT Action, subject to Action behavior and the 100,000-character request limit.

Not currently supported by official docs: using a GPT Action to fetch and store the authoritative whole ChatGPT/GPT conversation transcript exactly.

Best exact alternative: own the chat surface and persist every turn yourself, or rely on user-initiated ChatGPT data export for account-level historical records.
